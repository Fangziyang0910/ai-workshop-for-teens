# 课程服务器安装指引

本指引供教师及学校技术负责人使用。服务器采用Ubuntu 24.04 LTS、x86-64架构，建议4核CPU、8GB内存、80GB磁盘。学生只通过浏览器访问，不在学生电脑安装服务器软件。

Dify采用1.17.1。课程附加配置关闭不使用的Agent V2服务，保留Chatflow、知识库、插件和流程协作。安装包采用Docker Engine 29.9.1、Compose 5.6.0。课程附加配置要求Compose不低于2.24.4。

## 一、传入安装材料

将整个“本地资源”目录复制到服务器，例如`/opt/ai-course/resources`。以下用此路径举例；学校使用其他位置时统一替换。复制后先执行资源校验。

```bash
cd /opt/ai-course/resources
python3 资源管理.py verify
```

Windows备课电脑可以使用PowerShell的`scp -r`传文件，也可使用学校已有的文件传输工具。使用自己的服务器用户名和地址，不把示例文字原样输入。

```powershell
scp -r "本地资源/." 用户名@服务器地址:/opt/ai-course/resources/
```

命令复制“本地资源”内的内容；目标目录下应直接看到`资源清单.json`，不要再套一层同名文件夹。远程用户须对目标目录有写入权限。第一次传输前由服务器管理员创建目录并授权。`下载文件`必须一并传入；只下载GitHub源码不会包含大型安装包。

## 二、安装容器环境

新建Ubuntu主机可以使用本地五个官方DEB包安装。Ubuntu系统库依赖通过学校允许的Ubuntu软件源补齐。

```bash
cd /opt/ai-course/resources/下载文件/04_服务器依赖/Docker_Ubuntu2404_amd64
sudo apt-get update
sudo apt-get install ./*.deb
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version
```

已有Docker服务的主机先查看版本和正在运行的应用。兼容时直接使用，不执行上面的替换安装。后续命令示例按当前账号有Docker操作权限编写；没有权限时在`docker`前加`sudo`。Docker权限相当于服务器管理权限，不授予学生。

## 三、建立独立的课程目录

只在新的课程目录执行。若`runtime/dify-1.17.1`已经存在，应先确认它是否为运行实例，不重复解压覆盖。

```bash
cd /opt/ai-course
mkdir -p runtime
cd runtime
python3 -m zipfile -e ../resources/下载文件/02_Dify/dify-1.17.1.zip .
cd dify-1.17.1/docker
cp /opt/ai-course/resources/compose.course.yaml compose.course.yaml
```

只对新解压的目录执行配置生成。该工具遇到已有`.env`会停止，避免改写运行实例的数据库密码和加密密钥。

先做教师个人演练时，使用本机入口：

```bash
python3 /opt/ai-course/resources/准备服务器配置.py . --url http://localhost:18080
python3 /opt/ai-course/resources/准备离线插件.py .
```

直接部署正式课堂实例时，将第一条命令的URL换成学校HTTPS课程地址。两种方式只选一种。生成文件包含随机数据库密码和内部密钥，权限为仅文件所有者可读写；不把`.env`复制到学生设备或GitHub。

离线插件工具将62个Python 3.12/Linux依赖复制到`course-wheels`，建立本地索引。附加Compose配置把该目录只读挂载到插件容器；`PIP_MIRROR_URL=file:///opt/course-wheels/simple`使通义插件从本地安装依赖。不要删除这行，也不要关闭官方插件签名校验。

## 四、导入镜像并启动

本地镜像包、镜像版本及摘要见[资源目录](README.md)。导入不包含教师账号、模型密钥或学生数据。

```bash
docker load -i /opt/ai-course/resources/下载文件/04_服务器依赖/dify-course-images.tar
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml config --quiet
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml up -d --pull never
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml ps -a
```

初次启动会建立数据库。`init_permissions`以退出码0结束属于正常情况，其他长期服务应保持运行。查看故障时，先看对应服务最近100行日志，不反复删除数据卷。

```bash
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml logs --tail 100 api worker plugin_daemon
```

网页只绑定服务器本机`127.0.0.1:18080`。教师在Windows PowerShell中建立SSH转发，并保持该窗口打开：

```powershell
ssh -N -L 18080:127.0.0.1:18080 用户名@服务器地址
```

浏览器访问`http://localhost:18080/install`，创建教师管理员。不要把此演练地址发给学生；学生电脑上的localhost指向学生自己。

## 五、配置课堂HTTPS入口

正式上课前，将学校域名解析到课程服务器或学校访问网关。由网关提供TLS证书、关闭匿名应用接口，教师和学生使用Dify小组账号登录后预览作品。网关转发到`http://127.0.0.1:18080`。下面的Nginx配置适用于网关与Dify在同一台服务器的情况。实际域名和证书路径由管理员填写。先通过SSH完成管理员初始化，再启用正式入口。

```nginx
server {
    listen 443 ssl;
    server_name ai.school.example;
    ssl_certificate /etc/nginx/certs/course-fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/course-key.pem;
    client_max_body_size 20m;

    # This course uses authenticated console previews only.
    location ^~ /api { return 403; }
    location ^~ /v1 { return 403; }
    location ^~ /openapi { return 403; }
    location ^~ /e/ { return 403; }
    location = /install { return 403; }

    location / {
        proxy_pass http://127.0.0.1:18080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_buffering off;
        proxy_read_timeout 300s;
    }
}
```

这里允许`/console/api`，由Dify自身验证教师和小组登录；禁止独立Web应用使用的匿名`/api`入口及课程不使用的服务API、开放API和触发器。配置生成工具同时关闭自主注册和创建工作区。课前用未登录浏览器确认不能运行应用，再用小组账号验证预览。

学校如已有基于会话的统一认证，可在外层继续使用。不要直接用HTTP Basic认证包住所有Dify路径：它与独立Web应用的Bearer认证共用Authorization请求头，会造成冲突。需要发布独立Web应用时，另按学校的会话认证方案开放对应路由；基础课程不需要这一步。

如果先做过localhost演练，再改正式入口，编辑已有`.env`中的以下变量，不重新生成密钥：

- `CONSOLE_API_URL`、`CONSOLE_WEB_URL`、`SERVICE_API_URL`、`APP_API_URL`、`APP_WEB_URL`、`FILES_URL`、`TRIGGER_URL`改为学校HTTPS地址。
- `NEXT_PUBLIC_SOCKET_URL`改为同域名的`wss://`地址。
- `ENDPOINT_URL_TEMPLATE`改为`https://学校域名/e/{hook_id}`。

修改后运行同一条`docker compose ... up -d --pull never`。验证登录、流程编辑、流式回答和邀请链接。服务器公网只开放必要的HTTPS及受限管理入口，不开放数据库、Redis、插件调试端口。

## 六、配置邮件与小组账号

在`.env`补入学校邮件服务的参数。Dify 1.17.1的选配邮件示例位于`envs/core-services/shared.env.example`；按学校SMTP服务填写，不使用示例密码。

```dotenv
MAIL_TYPE=smtp
MAIL_DEFAULT_SEND_FROM=学校许可的发件地址
SMTP_SERVER=学校SMTP主机名
SMTP_PORT=587
SMTP_USERNAME=学校SMTP用户名
SMTP_PASSWORD=学校SMTP密码或应用专用密码
SMTP_USE_TLS=true
SMTP_OPPORTUNISTIC_TLS=true
```

上述例子使用587端口与STARTTLS；如果学校使用465隐式TLS，设置`SMTP_PORT=465`、`SMTP_USE_TLS=true`、`SMTP_OPPORTUNISTIC_TLS=false`。重启课程服务后，先邀请一个学校管理的测试邮箱，确认能打开邀请链接、设置密码和登录，再邀请16个小组邮箱。教师账户用Owner或Admin，小组用Editor。

## 七、安装插件并接入模型

1. 在Dify“插件”选择从本地文件安装，上传`下载文件/02_Dify/tongyi-0.2.23.difypkg`。
2. 等待安装完成。插件签名保持验证；Python依赖从前面准备的本地索引取得。
3. 在设置中添加通义自定义语言模型：`qwen-plus-2025-12-01`。填写百炼北京业务空间API Key及API Host。Host统一填写主机名，例如`业务空间ID.cn-beijing.maas.aliyuncs.com`。
4. 上下文长度设8192，最大输出512，温度0.2，函数调用关闭，保留默认非思考模式，不启用联网搜索。
5. 导入第6课DSL，选择模型，输入一个短问题。确认服务返回完整文字后，再建立资料库和导入第7、8课模板。

具体节点、资料库和学生操作见[语言项目操作手册](../语言项目操作手册.md)。三个DSL不包含教师Key和知识库正文。第7、8课导入后必须选择本组资料库。

插件安装失败时查看`plugin_daemon`日志：本地索引路径错误先查挂载与`course-wheels/simple`；缺少依赖先重新校验62个wheel；模型401、429和型号不存在则按语言操作手册处理。安装成功不等于模型账号已经开通。

## 八、备份和恢复

课程服务器目录包含数据库、文件、插件、配置和知识库，不能只备份DSL。小规模课程可以在维护窗口停止课程服务后备份整个目录。教师另保存16组的DSL和资料原文，便于单组恢复。

```bash
cd /opt/ai-course/runtime/dify-1.17.1/docker
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml stop
cd /opt/ai-course/runtime
sudo tar -czf /opt/ai-course/ai-course-backup-日期.tar.gz dify-1.17.1/docker
cd dify-1.17.1/docker
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml start
```

把“日期”替换为北京时间日期，使用新的备份文件名。备份完成后立即恢复服务。备份包含密钥和账号信息，只保存在教师受控位置；不要提交GitHub。恢复时先解压到独立目录，检查配置和端口，再启动，不覆盖唯一运行实例。

## 九、联网范围

课堂必须能访问学校课程入口和百炼北京模型接口。服务器依赖、通义插件和基础知识检索可从本地材料完成准备。软件更新、域名证书续期、邮件和系统安全更新仍由技术负责人维护。这里的“本地资源”指安装和教学材料已留存，不表示语言模型在办公电脑上离线运行。
