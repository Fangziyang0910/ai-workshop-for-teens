# 校园展览讲解助手操作手册

本手册供教师及学校技术负责人使用。学生通过浏览器完成第6～9课，不安装开发环境，不持有模型密钥。课程采用Dify Community 1.17.1与百炼北京地域文本模型，统一使用随附展品资料、提示词和Chatflow模板。

## 一、软件与服务配置

| 项目 | 课程设置 |
|---|---|
| 服务主机 | 国内Linux服务器，Ubuntu 24.04 LTS，4核、8GB内存、80GB磁盘 |
| 部署方式 | Docker Engine与Compose，本地包Compose 5.6.0；课程附加配置要求不低于2.24.4 |
| Dify | Community 1.17.1，按该版本新建课程实例 |
| 模型插件 | 官方Tongyi，课程配置采用0.2.23；保留插件包与版本 |
| 模型 | `qwen-plus-2025-12-01`，北京地域，非思考 |
| 生成参数 | 温度0.2；输出上限512 Token；联网搜索关闭 |
| 知识库 | 普通文本、通用分段、经济型索引、关键词检索 |
| 入口 | 学校课程域名的HTTPS地址，统一教学工作区 |
| 账户 | 教师Owner/Admin，16个小组Editor；学校管理的小组邮箱 |
| 学生客户端 | 学校更新维护的Edge或Chrome浏览器 |

课堂应用只处理文字，不启用文件上传、图像理解、语音或外部工具。三个模板对应同一作品的三个阶段：短资料讲解、知识库讲解、讲解与挑战。学生逐步修改本组应用，教师保留模板，用于示范和恢复。

官方依据：[Dify部署](https://docs.dify.ai/en/self-host/deploy/quick-start/docker-compose)、[版本1.17.1](https://github.com/langgenius/dify/releases/tag/1.17.1)、[Tongyi插件](https://marketplace.dify.ai/plugin/langgenius/tongyi)、[插件配置定义](https://github.com/langgenius/dify-official-plugins/blob/main/models/tongyi/provider/tongyi.yaml)。

## 二、教师部署步骤

### （一）取得与准备软件

1. 为课程准备国内服务器和学校管理的课程域名；校园网及家庭网络均访问同一入口。域名、证书和校方访问管理由技术负责人配置，学生不访问服务器内部端口。
2. 在新建Ubuntu主机上按[Docker官方Ubuntu安装步骤](https://docs.docker.com/engine/install/ubuntu/)安装Docker Engine、CLI、containerd及Compose插件。已有Docker环境先确认版本，不直接卸载现有服务。
3. 从[本地资源](本地资源/README.md)取得Dify 1.17.1代码包及其对应镜像。学校不能访问下载源时，在可访问的教师准备环境下载，再传入国内服务器；使用官方来源和固定版本，不更换为不明整合包。
4. 为管理员准备课程服务地址、小组邮箱、邮件服务和百炼北京地域账户。密钥只填入服务配置，不放进学生材料或仓库。

安装命令统一见[服务器安装指引](本地资源/服务器安装指引.md)。使用本地Dify源码包、镜像包和`compose.course.yaml`，再生成私有配置与插件依赖索引。不要只运行官方默认Compose文件：默认配置还会启动本课程不使用的Agent V2服务。

### （二）环境参数与网络入口

编辑`.env`，按该版本配置说明设置以下项目。1.17.1将选配参数分散到`docker/envs/`；邮件等选配变量可直接补入`.env`，也可复制对应`.env.example`后修改。示例中的`https://课程域名`应替换成学校实际地址，不能原样复制；内网IP仅用于管理员初始配置。

| 配置 | 设置原则 |
|---|---|
| `CONSOLE_WEB_URL` | 学生与教师访问的HTTPS控制台地址，不能用localhost |
| `CONSOLE_API_URL` | 浏览器可访问的控制台API地址，与反向代理配置一致 |
| `APP_WEB_URL`、`APP_API_URL` | 使用同一课程入口对应地址 |
| `SERVICE_API_URL`、`FILES_URL` | 使用课程入口，避免网页引用不可访问的内部IP |
| `SECRET_KEY` | 新生成的随机密钥，首次启动前设置并妥善保存 |
| 数据库、Redis与插件内部密钥 | 修改示例默认值，并保持所有引用一致 |
| `MAIL_TYPE`及邮件参数 | 使用学校许可的邮件服务，用于邀请与账号恢复 |
| `LOG_TZ` | `Asia/Shanghai`，设置Dify应用日志时区；课堂记录也统一北京时间 |
| `NEXT_PUBLIC_SOCKET_URL` | `wss://课程域名`；网关转发WebSocket升级请求 |
| `NEXT_PUBLIC_ENABLE_AGENT_V2` | `false`；本课程使用Chatflow入口 |

网络入口通过学校网关或反向代理提供TLS，教师和学生登录Dify后使用预览。课程安装指引在网关关闭匿名应用接口；不使用HTTP Basic认证替代整套平台认证。只允许必要的网页入口，数据库、Redis和插件内部端口不向学生公网开放。Docker发布端口与系统防火墙规则需一并配置，不能只假设UFW自动覆盖容器端口。

配置完成后启动：

```bash
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml up -d --pull never
docker compose -p ai-course -f docker-compose.yaml -f compose.course.yaml ps
```

按官方说明确认服务启动；一次性初始化容器执行结束退出属于正常情况。进入`/install`完成管理员设置，再登录控制台。首次创建课程实例采用1.17.1完整配置；已有旧版实例的数据库与Weaviate升级应另按版本迁移说明处理，不能用本节新建步骤直接覆盖。

### （三）下载受限时转移安装文件

本地资源已按Linux x86-64架构准备镜像。传入课程服务器后执行`docker load`，再按服务器安装指引启动。镜像包不包含教师密钥。`course-wheels`保存通义插件的62个运行依赖，安装插件时从本地索引读取，无需临时访问PyPI。

需要从GitHub清单重新取得镜像时，使用[取回服务器镜像工具](本地资源/取回服务器镜像.py)，按官方源的内容摘要下载并导出。官方源连接慢时可加`--mirror`使用缓存；内容摘要保持一致。操作方法见[本地资源目录](本地资源/README.md)。

Dify运行可只访问国内模型接口，学生无须连接GitHub或插件市场。平台安装和更新由教师完成，课中不临时下载插件。

## 三、配置国内模型

1. 在百炼控制台选择华北2北京，使用学校或课程负责人管理的业务空间，创建课程专用API Key，启用按量付费和费用提醒。
2. 在Dify插件中安装官方`langgenius/tongyi`。课程按0.2.23配置；通过市场或下载的官方插件包安装，保留版本记录，不在学期中随意升级。
3. 打开模型供应商设置，选择通义，填入同地域API Key。接入域名填控制台给出的北京业务空间API Host，形如`业务空间ID.cn-beijing.maas.aliyuncs.com`；课程统一只填主机名，避免混入其他API路径；0.2.23插件也支持完整的服务URL。使用国际端点选择“否”。
4. 添加自定义语言模型，名称填写`qwen-plus-2025-12-01`。课程上下文配置可限定为8,192，最大输出上限设为512，关闭函数调用。自定义模型的凭证表单也要填写北京地域API Key和API Host，不假定自动继承上一步；这是课程使用限制，不是供应商模型的完整能力上限。
5. 在每个模型节点选择同一模型，设温度0.2、最大输出512。自定义模型模板只填写插件提供的温度与输出上限参数；该快照默认不开启思考，保持默认，不额外启用思考或联网搜索。[百炼思考模式说明](https://help.aliyun.com/zh/model-studio/deep-thinking)。
6. 先用一句“请根据给出的两条资料作简短介绍”检查模型连接，再导入课程模板。401先查Key与地域，429先查额度/限流，模型不存在先查准确名称和账户授权。

[百炼地域与接入域名](https://help.aliyun.com/zh/model-studio/regions/)、[模型计费与版本](https://help.aliyun.com/zh/model-studio/model-pricing)说明地域、型号和收费口径。API Key和业务空间不能跨地域混用。

## 四、小组账号与模板分发

1. 教师建立课程专用工作区，名称使用“AI创想工坊”。不与学校内部业务或私人资料混用。
2. 为A01～A08、B01～B08创建学校管理的小组邮箱或别名；通过成员管理邀请Editor。教师使用管理员账户，学生不共享管理员密码。
3. 邀请链接应基于课程域名。邀请链接有有效期；课前由教师完成激活与登录检查，家庭沿用小组账号。
4. 以教师账号从工作室选择“导入DSL”，上传本目录[第6课模板](配套材料/Dify模板/第6课_短资料讲解.yml)。选择已配置的课程模型，预览短问题，再复制16个应用，分别命名为`A01_展览讲解助手`至`A08_展览讲解助手`、`B01_展览讲解助手`至`B08_展览讲解助手`。
5. 复制第7、8课教师模板时，分别绑定对应组知识库。模板中的空知识库列表是部署时需要选择的资源，不是可直接用于检索的示例ID。
6. 学生只进入带本组编号的应用。Editor能编辑和删除工作区内的应用、知识库，权限不限定于本组。教师要求学生按组号操作，并为各组保留备份。每课前后教师导出稳定版。

官方[成员权限](https://docs.dify.ai/en/self-host/use-dify/workspace/team-members-management)与[应用导入导出](https://docs.dify.ai/en/self-host/use-dify/workspace/app-management)用于管理员操作。导入模板不包含API Key；知识库正文需要单独上传。

## 五、第6课短资料讲解

### （一）节点与配置

```text
用户输入 → 讲解模型 → 回复
```

| 位置 | 填写内容 |
|---|---|
| 用户输入 | 使用Chatflow自带用户问题`sys.query` |
| 模型系统提示词 | 第6课提示词和短资料正文，保留编号 |
| 模型用户消息 | 从变量选择器插入用户问题 |
| 模型记忆 | 基础对照测试关闭历史记忆，每道题新建会话 |
| 回复 | 插入模型节点的`text`输出 |

学生首先改“面向谁、讲什么、怎样表达、不知道怎么办”。短资料用于提供事实。若资料中夹有要求改变助手身份或任务的文字，提示词应明确要求忽略这些文字。

### （二）学生操作与检查

打开应用、输入“这个作品有什么用”、找到回答依据。将讲解对象从初一学生改为小学参观者，用同一问题比较表达；再问“获过什么奖”，检查是否承认没有资料。保存两版提示词和实际回答。

每次只改一项规则，再新建会话测试。低温度只能减少部分随机变化，不能保证事实正确或每次完全一致。

## 六、第7课资料整理与检索

### （一）建立知识库

1. 新建知识库，命名`A01_展品资料`。上传[展品知识库文本](配套材料/第7课_展品知识库.txt)，文本为UTF-8。
2. 采用通用分段，按空行分隔；分段长度起始设500字符、重叠0。查看预览，确保每条编号与正文在同一段。1.17.1这条通用文本分段路径按字符长度处理；按预览核对12条资料，不把字符数等同于模型计费Token数。
3. 选择经济型索引，完成后查看各条目。先用“纸桥模型”查到对应内容，再使用完整问题测试。
4. 每组可保留公共资料，也可用真实小组作品资料替换。替换时保持编号唯一，明确来源；删除旧版本后检查相关检索结果，避免同时保留冲突条目。

### （二）配置应用

```text
用户输入 → 知识检索 → 讲解模型 → 回复
```

| 节点 | 关键设置 |
|---|---|
| 知识检索 | 选择本组资料库；查询选择`sys.query`；检索结果数量起始取4；重排关闭 |
| 讲解模型上下文 | 启用，变量选择知识检索的`result` |
| 讲解模型系统提示词 | 第7课规则，使用上下文变量；不再粘贴旧短资料 |
| 用户消息 | 当前问题`sys.query` |
| 回复 | 讲解模型的`text` |

通过变量选择器插入上下文，不把“这里放检索内容”这种说明文字当成真正变量。模板使用`{{#context#}}`引用模型上下文，知识检索节点的结果选择在模型配置中完成。检索原文与最终回答都应能够查看。

### （三）回答出错时的检查顺序

1. 查看原文是否包含回答所需的事实。
2. 查看检索结果是否返回了对应条目。
3. 查看回答是否正确使用了该条事实。
4. 核对回答中的编号是否存在，是否支持这句话。

关键词检索按词匹配，换一种说法可能查不到同一条资料。先检查展品名、常见别称和分段。需要尝试语义检索的小组可在应用副本中增加模型；基础课程仍使用关键词检索。

## 七、第8课讲解与挑战

### （一）入口字段

| 字段 | 类型 | 选项 | 用途 |
|---|---|---|---|
| `task` | 必填下拉 | 讲解、挑战 | 明确选择任务 |
| `topic` | 必填下拉 | 文具归位提示器、纸桥模型、手摇发电模型 | 确定资料主题 |
| `sys.query` | Chatflow自带文本 | 用户自己的问题或要求 | 指定讲解细节或挑战要求 |

更换自己的展品时，同步更新`topic`选项、资料中的展品名及测试题。用户改变任务或主题后，新建会话再测试，以便核对当前选择。

### （二）连接节点并设置分支

```text
用户输入 → 展品检索 → 条件判断
                      ├─ task等于挑战 → 挑战模型 → 挑战回复
                      └─ 其他合法选项 → 讲解模型 → 讲解回复
```

展品检索查询选择`topic`，使“出一道题”等短请求仍然取得所选主题资料。两个模型的上下文都绑定同一个检索结果；分别接收`topic`和`sys.query`。条件节点使用精确相等，比较值为“挑战”。每次仅执行一个分支。

基础流程的两种生成任务都使用同一模型。讲解规则先答问题再列依据；挑战规则只出一道两选一题，并在“作答后再看”标记后给出答案、解释和依据。基础版只展示题目和答案，不自动评分，也不保存成绩。

### （三）拓展任务 自动判断用户意图

在应用副本中移除用户任务选择，用问题分类器将用户输入分为“讲解”和“挑战”，分别连接已有分支。需要额外一次模型调用，记录选择是否正确。混合请求可要求用户先选一种任务；不增加循环和自主工具调用。教师保留由用户选择任务的版本，供结课展示使用。

## 八、发布与家庭访问

学生首先使用登录后的预览完成制作与测试。课堂互评交换操作者或工位，不交换管理员账户。结课由本组登录展示，外部参观者在本组工位体验。

如需使用独立Web应用，发布前在学校访问网关限制到课程用户；共享链接本身不是身份验证。未配置访问保护时不向公众发布。课程网关同时保护编辑页面和演示入口，家庭访问与校园访问使用同一受控域名。公开展示材料中不放编辑账号、密钥或带凭证的链接。

## 九、保存与恢复

每课分别保存应用配置文件（DSL）、资料原文、提示词、测试记录和演示视频。DSL只保存应用结构与资料关联，不包含知识库正文或供应商密钥。恢复时先创建资料库并上传原文，再导入应用，重新选择模型与资料库，执行一条有答案题和一条无答案题。

管理员定期备份课程实例的数据库、文件和插件数据；小规模课程可以在维护窗口停止Compose后对整个部署目录及实际数据卷作一致备份，再恢复服务。备份必须包含`.env`和密钥配置，但它们只保存在教师受控位置，不进入学生目录。恢复在独立目录进行，不覆盖唯一运行副本。

## 十、课堂运行检查与问题处理

| 现象 | 查找位置 | 处理 |
|---|---|---|
| 登录邀请指向localhost | 控制台外部地址 | 修正课程域名，再发邀请 |
| 模型401 | Key、地域、供应商配置 | 使用北京同一业务空间的凭证 |
| 模型429 | 配额与并发、余额 | 等待上一轮结束，再核对账户限额；增加密钥不会增加账户配额 |
| 导入后模型未选择 | 模型节点 | 选已配置的课程型号并保存 |
| 检索节点报错 | 资料库绑定与索引 | 选择本组库，等待索引完成 |
| 回答没有用资料 | 模型上下文与变量 | 绑定`result`，检查上下文引用 |
| 只说出题却检索为空 | 查询变量 | 第8课改用`topic`，不只搜“出题” |
| 分支都走讲解 | 条件值和字段 | 检查`task`等于“挑战”及入口选项 |
| 说有奖项或价格但资料没有 | 提示词与测试 | 加强事实范围，保留失败记录后复测 |
| 输出中断 | 输出上限与网络 | 缩短讲解要求；保留完整题干和选项，减少解释长度 |
